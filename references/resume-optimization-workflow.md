# ToB 销售简历优化工作流

## 触发场景
用户给出候选人简历（PDF/图片）+ 聊天记录/项目经历，要求往 ToB 销售方向优化。

## 工具链
1. **PDF 提取**：用 pymupdf（Python 3.14 环境）读取简历文本
   ```bash
   /c/Users/MECHREVO/AppData/Local/Python/pythoncore-3.14-64/python.exe -c "
   import pymupdf
   doc = pymupdf.open('path.pdf')
   for page in doc: print(page.get_text())
   "
   ```
2. **图片 OCR**：用 winocr（Python 3.14 环境）读取聊天记录截图
   ```bash
   /c/Users/MECHREVO/AppData/Local/Python/pythoncore-3.14-64/python.exe -c "
   from PIL import Image; import winocr
   img = Image.open('path.png')
   print(winocr.recognize_pil_sync(img, 'zh-CN')['text'].replace(' ', ''))
   "
   ```
3. **Word 输出**：python-docx 生成 .docx，风格简洁（见下方格式规范）

### 说服能力提取（从聊天记录中挖掘）
聊天记录中往往藏着候选人真实的说服案例，要主动提取：
- **说服对象**：谁？（合作伙伴/决策者/终端客户）
- **说服方法**：怎么做的？（数据驱动/迂回表达/链条突破）
- **说服结果**：成交了什么？（金额/人数/续约）

常见说服信号词：
- "我跟他讲"、"说服他"、"用数据证明"
- "先联系A，A帮我介绍B"（决策者链条）
- "他性格XX，所以我换了种方式"（风格适配）
- "最后同意了"、"促成了合作"

### STAR 法则应用
每条核心经历必须包含：
- **S（背景）**：什么情况下，面临什么挑战
- **T（任务）**：要完成什么
- **A（行动）**：具体做了什么（动作可复制）
- **R（结果）**：量化数据（人数、金额、转化率、场次、准确率）

写法选择：
- 一句话内嵌 STAR（适合非核心经历）：「在XX背景下，通过XX行动，实现XX结果」
- 子弹点拆开（适合核心亮点）：背景/行动/结果各一行缩进

## Word 输出格式规范（KoWin 偏好）
- **不要**：表格、边框、底线装饰、颜色、图标
- **要**：纯文字 + 加粗标题 + 圆点列表，类似 md 渲染效果
- 字体：微软雅黑 + Calibri
- 页边距：2cm
- 三级标题：h1(18pt) > h2(12pt) > h3(10.5pt)

## 完整流程
1. 读取所有材料（PDF + 图片/聊天记录）
2. 用 tob-coacher 3E 跨行映射表翻译经历
3. 从聊天记录提取说服/沟通/销售案例
4. 按 STAR 法则重写每条经历，补数据补结果
5. 输出 .md 文件
6. 用 python-docx 生成 .docx（简洁格式）
7. 总结优化点清单供用户确认

## 关键教训（KoWin 简历优化 session）

### 文件命名：直接覆盖原版
- ❌ 每次另存为 v2、v2.1、v2.2…（用户明确纠正）
- ✅ 直接覆盖原文件 `XXX_优化简历李克旺.docx`
- 用户说"直接在原版上面修改即可"时，不要创建版本号后缀的新文件

### 描述详略度校准
- **课程项目经历**：每个项目 2 条 bullet 即可，不要分子标题展开（用户说"课程项目不用太细"）
- **核心实习经历**（如唯一沾边的金融销售实习）：可以展开到 3 个小标题 × 2-3 条 = 7 条左右
- **其他实习/校园经历**：1 个小标题 × 2-3 条 = 2-3 条
- ⚠️ 用户说"细化"≠ 加子标题+堆 bullet，而是每条内容稍微丰富一点

### 冗余检查
- 完成初稿后，逐板块检查是否有重复表述（如"全链条认知"出现两次）
- 合并语义重叠的小标题（如"客户对接"和"路演统筹"可合并为"客户对接与路演协调"）
- 用户反馈"感觉有些重复冗余"是常见返工原因，应在输出前自检

### 主观评价替换
- ❌ "获带教老师'细致靠谱'评价"——主观评价没有数据支撑，招聘方不认
- ✅ 换成具体行为："同时承接临时性资料整理与接待支持任务，保障团队日常运转"
- 原则：简历里只写能验证的事实，不写无法佐证的主观判断

### 页面控制
- 用户说"减少到X页"时，不要只删末尾板块，要跨板块合并精简
- 优先合并方式：语义重叠的小标题合并（如"研究支持"+"团队协作"→"研究支持与团队协作"）
- 其次：每个小标题内减少1条bullet
- 最后：删除纯装饰性内容（如兴趣爱好、主观评价）

### python-docx 生成模式
- 用脚本 `gen_final.py` 生成，运行后立即删除脚本
- 不要导入 `fitz`（pymupdf 的 import 名），用 `pymupdf` 模块名
- pymupdf 装在 Python 3.14 环境，hermes venv 是 3.11，需要调用 3.14 的 python.exe
- bash 下 Windows 路径用 `/c/Users/...` 格式，不要用反斜杠

### 去AI味：对比其他AI输出
- 用户可能拿豆包/Kimi等其他AI的版本来对比，如果对方版本更好（更自然、更简洁），直接采用
- 本session发现的额外"大词"：「搭建标准化分析框架」「转化链路设计」——换成「进行对比分析」「转化路径」
- 核心原则：简历是写给招聘方看的，不是写给AI看的。像一个真实的人在讲述自己的经历，而不是一台机器在生成报告
